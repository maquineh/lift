# Source diagnostics and generated-file reuse

[Português do Brasil](diagnostics-and-build.pt-BR.md) · [User guide](../README.md)

The CLI is the only compiler crate that depends on Ariadne 0.6.0. Lexer/parser/sema continue producing their existing diagnostics and half-open byte spans; no presentation dependency enters AST or HIR. `diagnostics.rs` renders one Ariadne report per source error, with a primary label and an optional `local relacionado` label in the same report. Source failures still return exit code `1`.

Dependency API reference: [Ariadne 0.6.0](https://docs.rs/ariadne/0.6.0/ariadne/).

The renderer explicitly uses `Config::with_index_type(IndexType::Byte)`. Spans remain UTF-8 byte offsets rather than being converted to character offsets. Empty spans at EOF remain empty. Bounds and UTF-8 boundaries are defensively normalized only for rendering. The displayed line/column and source excerpt are computed by Ariadne. Colors are enabled only for an interactive stderr terminal without `NO_COLOR`; captured output has no ANSI colors. If rendering fails, the CLI attempts a plain path/message fallback and still reports failure.

This covers lexical, syntax, and semantic errors in the entry file and its imported modules. SourceId selects the source of each label, including secondary labels in another file. Cargo/rustc diagnostics retain Cargo's rendering and refer to generated Rust; there is no Rust-to-Truxt source mapping yet. Tests check multibyte Unicode, EOF, exit codes, excerpts, and related labels without relying on a complete layout snapshot.

## Reuse generated bytes

The CLI reads the existing `src/main.rs` and `Cargo.toml` and writes a file only if its bytes differ. Missing files are created; a read or write failure remains a CLI error. The same helper preserves unchanged embedded-core files. No hash database or process-wide state is introduced.

The acceptance test sets generated-file modification times to a fixed historical timestamp, reruns `check`, and verifies that identical files keep both bytes and timestamps. A changed constant updates Rust while preserving an unchanged manifest; adding core usage updates the manifest. This avoids sleeps and assumptions about filesystem clock resolution.

This is output-write reuse, **not a complete content-keyed compiler cache**. Every command still reads/tokenizes/parses/analyzes/emits the program and invokes Cargo. Cargo retains its own incremental artifacts. Compiler/toolchain versions, dependency configuration, and other inputs are not represented by a Truxt cache key.

## Next boundary

Explicit file imports now follow [the module contract](modules.md). Spans carry SourceId while retaining byte offsets and legacy source-zero APIs. A project manifest, namespaces, and a dependency-keyed cache remain outside that contract.
